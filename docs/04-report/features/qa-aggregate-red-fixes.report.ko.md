## 6. 교훈 및 회고

### 6.1 잘된 점 (Keep)

- 사전 소화된 브리프: 수정 에이전트는 근본 원인을 재도출하지 않았고 3라운드 각각 ~4.5분 소요.
- 실패 시 동일 에이전트 재사용 — "qafixes-impl"이 새 에이전트의 컨텍스트 재구축 없이 라운드 간 컨텍스트 유지.
- 직접 레지스트리 프로브(`19 13 6 16 3` 출력 등)로 계약 논쟁을 한 줄 검증으로 전환.

### 6.2 개선 필요 (Problem)

- 2라운드 브리프 숫자는 파생 열거가 아닌 정확한 접근자(listByServer) 프로브에서 나와야 함 — MAIN의 파생 카운트가 틀렸음.
- 마스킹된 형제 어설션(파일이 크래시하면 이후 어설션이 실행되지 않음)은 한 수정이 다음 실패를 드러낼 수 있음 — 크래시 파일 수정 시 N라운드 예상 필요.

### 6.3 다음에 시도 (Try)

- 모든 숫자 계약에 프로브 우선 브리프: 접근자 프로브 없는 브리프 숫자 금지.
